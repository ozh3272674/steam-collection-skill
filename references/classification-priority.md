# 分类优先级链（铁律）

用户于 2026-10-10 明确立规，任何分类调整都必须遵守，不得违背。

## 一、优先级链（从高到低）

```
C 厂商类  >  C-Z95 / C-Z96 / C-Z97 / C-Z99  >  D 类型类  >  E 其他类
```

判定为**逐级下降**，命中即停：

1. **先看厂商**。能归入某个厂商收藏集（`C-<桶><编号> 厂商-XXX`）的，一律进厂商类，
   **不再往下看**。厂商口径 = 开发商 / 发行商（发行商优先）。
2. **归不了厂商**，才按筛选标准依次问四个语义类目，命中即停：
   | 编码 | 类目 | 筛选标准 |
   |---|---|---|
   | `C-Z97` | 厂商-中国联网 | 中国厂商 + 联网（Steam category id ∈ {20,27,36,38}） |
   | `C-Z99` | 厂商-中国单机 | 中国厂商 + 单机 |
   | `C-Z95` | 厂商-国外联机 | 国外厂商 + 联网 |
   | `C-Z96` | 厂商-国外多端游戏 | 国外厂商 + 有移动端（iOS/Android）或多端发行 |
3. **四个 Z 类全不进**，才按标签进 `D` 类型类。
4. **D 也不进**（无合适类型标签等），才进 `E` 其他类。

**关键点**：Z95/96/97/99 是「厂商之外的语义类」，它们排在 D 之前、E 之前，
但排在**真正的厂商类之后**。一个游戏若同时满足厂商条件和 Z 类条件 → **必须进厂商类**。

## 二、禁止下级掏空上级（硬约束）

> **下级分类的操作不得导致上级分类消失。若会导致，则不执行该操作。**

- 上级分类指优先级链中更靠前的层级。
- 典型违规案例（2026-10-10 实测踩到）：
  `C-F60 厂商-Fireproof Games`全库只有 The Room 四部曲 4 款。
  把这 4 款迁到 `C-Z96 厂商-国外多端游戏` 后，C-F60 变空 → 被清理删除。
  **这违反本规则**：C-Z96 是下级，它的存在不应导致上级厂商类 C-F60 消失。
  正确处置 → The Room 四部曲**留在 C-F60**，不进 C-Z96。
- 因此：**空的厂商收藏集不得由下级迁出造成**。若某厂商类因正常玩法归类而变空，
  应先停下来向用户确认，不得自动删除。

## 三、执行前自检（每次调整必过）

```
1. 这款游戏有厂商吗？
   有 → 进厂商类，停止。下面对 Z/D/E 的判断全部不执行。
   无 → 继续 2。
2. 能进 C-Z95/96/97/99 吗？能 → 进，停止。
3. 能进 D 类型吗？能 → 进。
4. 否则 → 进 E 其他。
5. 本次操作会不会让任何更高级的收藏集变空？
   会 → 停止该操作，向用户说明并请其定夺。
```

## 四、与其他规则的关系

- **互斥原则仍然有效**：每款静态游戏只属于一个收藏集，跨收藏集重复数必须为 0。
  A 类动态「正在玩」是唯一例外，可与静态类共存。
- **本规则不改变编号体系**：桶内步长 5、编号写死、已有编号永不重排。
- **基线约定**：对游戏库存的调整以你指定的那一版基线为准叠加增量，
  不以更早期的草稿方案（如 `v7/categories.json` + `preclassification.csv`）为基线。
