# 地区语义类目：C-Z97 / C-Z99 的口径与扩展

优先级链里的四个 Z 类是「厂商之外的语义类」。本文专门讲 Z97/Z99 的地区判定口径，
以及把口径从「中国」扩展到「中日韩（CJK）」时需要注意的事。

> 当前口径见 `classification-priority.md`。本文讲**口径的边界与扩展方法**。

---

## 一、联网 / 单机判定轴

沿用项目既有口径（Steam `appdetails` 的 `categories` 数组）：

```
联网 → Steam category id ∈ {20, 27, 36, 38}
否则 → 单机
```

**先验证这条轴在你自己的基线上是否成立**，再依赖它做迁移：

```python
ONLINE = {20, 27, 36, 38}
hit  = [a for a in members if set(meta[a]["categories"]) & ONLINE]
miss = [a for a in members if not set(meta[a]["categories"]) & ONLINE]
print(f"命中 {len(hit)} / 未命中 {len(miss)}")
```

实测偏差可参考：某 3991 款规模的库中，Z97 的 81 款有 15 款未命中该轴，
Z99 的 182 款有 6 款命中。**约 19% 的历史偏差意味着这条轴是启发式而非铁律**，
用它做大批量迁移前，先抽查未命中/命中名单确认。

## 二、把口径从「中国」扩展到「中日韩」

放宽口径时（典型动机：想把中日韩的游戏放在一起）需要两件事，且**必须同步做**，
否则名称与内容不符。以下是决策清单，**具体选哪个由用户裁决后再执行**。

### 2.1 名称冲突（先想清楚）

一旦把日韩游戏放进 `C-Z97 厂商-中国联网游戏`，名称就与内容矛盾了。三个方案：

| 方案 | Z97 新名 | Z99 新名 | 说明 |
|---|---|---|---|
| A | 厂商-国产联网游戏 | 厂商-国产单机游戏 | 沿用「国产」；名称与内容不符，但最简 |
| B（推荐） | 厂商-东亚联网游戏 | 厂商-东亚单机游戏 | 准确涵盖中日韩 |
| C（保守） | 维持「中国」 | 维持「中国」 | 日韩另建 `C-Z98` 独立集，不动 97/99 |

**编号永不重排**——`C-Z97`/`C-Z99` 无论改成什么名字，编码不变。

### 2.2 迁移动作

放宽口径后要同时处理**三类**游戏，只做第一类会留下错位：

1. **从 Z95（国外联机）/ Z96（国外多端）迁入** —— 这些是日韩游戏里被错放在「国外」的部分
2. **从 D 类型类迁入** —— 日韩独立工作室往往无厂商集，会掉进 D
3. **本就在 Z97/Z99 里的日韩游戏** —— 历史遗留的错位，最容易被忽略

> 第 3 类最隐蔽：分类时按「这游戏有中文运营/在 Steam 国区热卖」放进 Z97/Z99，
> 但开发方其实是 NEXON、Netmarble、BANK OF INNOVATION。

### 2.3 迁移前必须核实的清单

厂商名匹配**只能召回候选**，不能直接下结论。以下几类极易误判：

- **壳公司马甲**：`KAGAMI WORKs` 实为成都公司；`NekoNeko Soft` 实为中国 Nekoday
- **同名干扰**：`MOR Museum` 是加拿大平台，与森美术馆无关；`Shiro Games` 是法国
- **上市地 ≠ 开发地**：`Bank of Innovation` 是**日本**东证 4393，中文圈常误认韩国
- **规则 ≠ 国籍**：雀魂 MahjongSoul 做日麻规则，但开发方是**中国**猫粮工作室
- **同名不同司**：`Somi`（韩国釜山个人开发者）≠ `Michał Diduch`（波兰）
- **子串误命中**：`nc` 命中 `Inc.`、`snk` 命中 `Snkl Studio` —— 一律用词边界

## 三、地区判定的正确姿势

**先抽去重厂商 → 建表 → 只查表，不逐款游戏查。**

```
1. 从 developer + publisher 抽去重厂商名单
2. 对名单联网核实地区（每个厂商最多 1 次 WebSearch）
3. 产出 厂商 -> {region, reason} 表，此后增量直接复用
4. 用表回填游戏
```

输出格式（**只用序号**，厂商名常含英文逗号，写名字会破坏 CSV）：

```
序号,地区,依据
```

- 地区码：`CN` / `JP` / `KR` / `EUUS` / `OTHER`
- **`CN` = 中国大陆 + 港澳台**；中国团队注册海外 → 仍 `CN`，依据注明
- 查不到 → `OTHER`，依据写 `【存疑】`
- 拿不准的单列「存疑」清单交用户裁决，**不要猜**

厂商级判定的完整方法（母子三段结构、集团口径、吸收规则）见
**`vendor-attribution.md`**。

## 四、地区扩展类目的通用检查表

放宽任何语义类目的地域口径前，逐条过一遍：

- [ ] 新名称是否准确涵盖新范围？（否则改名与内容不符）
- [ ] 联网/单机轴是否已在本基线上验证过偏差？
- [ ] 是否处理了**三类**来源（Z 兄弟类 / D 类 / 本就错位在目标类的）？
- [ ] 每款候选是否核实过**开发方**而非只看发行商？
- [ ] 壳公司、同名干扰、子串误命中是否已排除？
- [ ] 存疑项是否单独列出而非硬判？
- [ ] 编码是否保持不变（编号永不重排）？
- [ ] 迁移是否会导致某上级分类变空？（空集清理铁律）
