# 编号体系与排序

编码格式、桶位分配、预留位规则。这套体系的核心设计目标是：
**编号写死、永不重排，改名不换号。**

---

## 一、编码格式

```
<大类>-<桶字母><编号> <中文标签>
```

| 实际编码 | 说明 |
|---|---|
| `C-V05 厂商-Valve` | **有**横杠 |
| `D-J15 类型-解谜` | **有**横杠 |
| `C-Z96 厂商-国外多端游戏` | **有**横杠 |
| `E001 其他-工具软件` | **无**横杠 |
| `E002` / `E003` | **无**横杠 |
| `A01 状态-正在玩` | **无**横杠 |

> ⚠️ **大组前缀的横杠并不统一。** 判断大组必须用 `startswith`，
> 不要假设都有横杠：
>
> ```python
> # 对
> if code.startswith("E"): ...
> if code.startswith("A"): ...
> # 错：startswith("E-") —— 会漏掉所有 E 类
> ```

---

## 二、编号只由名字决定

**编号的唯一依据是名字的首字母，之后永不重排。**

```
桶字母 = 名字首字母（中文转拼音）
```

| 名字 | 桶 | 编码 |
|---|---|---|
| Valve | V | `C-V05` |
| Klei Entertainment | K | `C-K15` |
| 解谜 | J | `D-J15` |
| 其他 | — | `E001`（例外，见下） |

**这条规则的直接推论：改名不换号。**

> 集团口径统一时 4 个集合改名，桶字母都没变：
> `WB Games→Warner Bros.`(W)、`BANDAI NAMCO→Bandai Namco`(B)、
> `GSC World Publishing→GSC Game World`(G)、
> `PlayStation Publishing LLC→PlayStation Publishing`(P)。
> **编号永不动。**

---

## 三、桶内分配：步长 5

桶内从 **05** 起、**步长 5**：

```
C-V05  C-V10  C-V15  C-V20  C-V25  ...
```

留空档给新成员插队，避免「加一个厂商就得重排所有编号」。

> 每个厂商只有 **4 个空位**（05/10/15/20 之间的空隙）。
> 这正是给系列紧跟厂商用的，但**同一个厂商的系列数超过 4 个时塞不下**，
> 需取舍 —— 通常让系列独立立集，或合并进兜底类。

核心排序函数：

```python
def sort_key(code):
    """大类字母 -> 分组序号；桶字母 -> 次序；编号 -> 数值"""
    prefix = code.split("-")[0] if code.startswith(("C-", "D-")) else code[0]
    letter = re.match(r"[A-Z]-([A-Z])", code)
    num   = re.search(r"(\d+)$", code)
    return (GROUP_ORDER.get(prefix, 9),
            letter.group(1) if letter else "",
            int(num.group(1)) if num else 0)
```

## 四、预留位与兜底类

| 编号 | 用途 |
|---|---|
| **96** | 预留 |
| **97** | 中文语义类目（当前：中国联网） |
| **98** | 预留 |
| **99** | **兜底类，必须是大类内最大号** |

**兜底类编号固定 99**，保证排序永远在最后。中间编号保持连续无空位。

## 五、类别命名标签

| 大类 | 标签 |
|---|---|
| A | `状态-` |
| C | `厂商-` |
| D | `类型-` |
| E | `其他-` |

### 四个 Z 类的语义

`C-Z` 系列是「**厂商之外的语义类**」，排在 D 之前、E 之前，
但排在**真正的厂商类之后**。

```
C-Z95  国外联机游戏
C-Z96  国外多端游戏
C-Z97  中国联网游戏
C-Z99  中国单机游戏
```

> `C-Z05 厂商-Zachtronics` 是正常的桶位厂商类，**不是** Z 语义类。
> 判断 Z 语义类要看 `C-Z9x` 的完整编码，别把 `C-Z05` 也算进去。

## 六、互斥原则

每款静态游戏**严格只进一个**静态收藏集，跨收藏集重复数必须为 **0**。

唯一例外：动态类 `A01 状态-正在玩`，可与静态类共存、无固定成员。

---

## 七、空集处理

| 情况 | 处置 |
|---|---|
| 自然废弃的空收藏集 | 可删 |
| **被下级分类掏空的厂商类** | **必须保留** —— 违反「下级不得掏空上级」铁律 |

见 `classification-priority.md` 第二节的硬约束。
