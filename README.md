# Steam 游戏库收藏集整理

> 一个交给 AI 助手执行的**技能包**：它会自动抓取你的 Steam 游戏库，设计一套收藏集分类，
> 逐款联网核实真实玩法，最后把收藏集写回你的 Steam 客户端。
> 你只需要回答几个问题、做几次确认。

一个技能包，把"给几百上千款游戏手动建收藏集"这件苦差事交给 AI。它读你的 Steam 库，
生成一套分类，逐款联网核实玩法，再写回客户端。每一步都会停下等你确认。

## 它解决什么问题

Steam 库一旦积累到几百款，"找游戏"就变成翻列表；手动建收藏集又极其枯燥——要一款款判断它属于
什么类型、哪个系列、哪家厂商。本项目把这件事交给 AI：

- **自动抓取**你拥有的全部游戏（含**家庭共享**的）；
- **自动设计**一套多维度的收藏集体系（也可完全自定义）；
- **联网逐款核实**每款游戏的真实玩法（Steam 商店标签泛滥，光看标签会分错）；
- **自动写回** Steam 客户端，打开库就能按收藏集筛选。

## 核心功能

- **联网核实，不靠标签**：让 AI 逐款搜索真实玩法来修正，准确率高于纯标签规则。
- **家庭共享也整理**：不只看"你拥有的"，也把家庭组共享的库一并纳入。
- **多维分类、自由筛选**：类型 / 系列 / 厂商 / 状态 / 特性各成维度，一款游戏可以属于多个维度。
- **类目质量可控**：内置"类目体检"（计算两两类目的重叠），避免"冒险 / 休闲 / 合作"这类宽泛类
  互相吸收、收藏集虚胖。
- **厂商维度智能细化**：把"其他厂商"里被埋没的**中国厂商**联网判定后单独成类，
  知名厂商（Rockstar、Cygames 等）逐个独立成类。
- **可选策略档位**：精细度（1 个主类型 / 1 主 + 2 次 / 不限）、是否建属性集、复核深度、预算——**由你决定**。
- **长任务不崩**：会话状态自动落盘（`HANDOFF.md`），跑几小时的任务换窗口也能接着干。
- **增量更新**：分类过一次后，新买 / 新领的游戏只处理新增部分，几分钟跑完。
- **写入安全**：Steam 运行守卫 + **双备份** + 原子写入，且**保护系统"收藏夹 / 已隐藏"**；随时可回滚。

适合谁：Steam 库里有几十到上千款游戏、想整理却懒得手动分的人；喜欢用 AI Agent 处理重复劳动的玩家；
想把自己的分类哲学（按类型？按厂商？按系列？）固化下来的人。

## 它是怎么工作的（四步流程）

每一步完成后都会**停下汇报、等你确认**，你随时可以纠错或叫停。

| 步骤 | 做什么 | 你需要做什么 |
|---|---|---|
| **① 抓取游戏列表** | 从 Steam 获取你的全部游戏（含家庭共享）；需要登录时会弹出浏览器让你登录 | 核对数量对不对 |
| **② 设计分类 + 预分类** | 给你一套类目提案（也可完全自定义），再做初步分类 | 确认类目合不合心意 |
| **③ 联网逐款复核** | 派 AI 子代理逐款搜索、核实真实玩法并修正 | 选择投入多少时间 / 预算，确认修正报告 |
| **④ 生成并写入 Steam** | 生成收藏集并写回 Steam；写前强制确认 | 完全退出 Steam；回复"确认写入" |

## 分类体系

分类体系采用 **A–F 六个维度**（A–E 为分类主维度，F 为可扩展的属性维度）：

- **A 状态**：正在玩 / 计划玩 / 长线常驻 / 暂时搁置（仅已安装，互斥）
- **B 系列**：同一 IP 的历代作品（如生化危机、最终幻想）
- **C 类型**：玩法类型（动作 / 角色扮演 / 策略 / 解谜 / 视觉小说 …）
- **D 厂商**：开发商 / 发行商（含中国厂商、知名厂商单独成类）
- **E 其他**：工具 / 软件 / 原声等非游戏内容
- **F 特性**：属性维度（多人合作、VR、手柄支持 …）

> 注意：项目内部的分类优先级链为 `C 厂商 > C-Z95/96/97/99 > D 类型 > E 其他`，
> 这里的字母是收藏集编号前缀（`C-`、`D-`、`E-`），与上面的维度字母是两套用途；
> 详见 [`SKILL.md`](SKILL.md) 与 [`references/classification-priority.md`](references/classification-priority.md)。

## 你需要准备

| 项目 | 是否必需 | 说明 |
|---|---|---|
| SteamID 或社区主页链接 | 必需其一 | Steam 客户端左上角 账户 → 账户详情 可见 |
| 本机装有 Steam 客户端 | 写入时必需 | 收藏集要写进本机 Steam |

## 安装与运行

**1. 获取任务包**

```bash
git clone https://github.com/xr05shino23/steam-collection-skill-plus
cd steam-collection-skill-plus
```

**2. 安装 Python 依赖**

```bash
pip install requests
# 若要用浏览器登录方式抓取，再装：
pip install playwright
playwright install chromium
```

`scripts/fetch_library.py` 的浏览器登录使用系统 Edge / Chrome；`playwright install chromium`
是它给出的兜底方案（见脚本第 22、177 行注释）。

**3. 填写配置**

把 `scripts/local_config.template.json` 复制为 `scripts/local_config.json`，填入 SteamID 等信息；
也可以直接在对话里把信息告诉 agent，让它代填。字段均可留空（对应功能降级），
也支持用环境变量覆盖（`STEAM_ID32` / `STEAM_VANITY` / `STEAM_ROOT` / `STEAM_PROXY` /
`STEAM_API_KEY` / `STEAM_LOGIN_SECURE`）。`local_config.json` 已被 `.gitignore` 排除，不会进仓库。

**4. 启动 agent**

对一个支持读取本地文件的 AI 助手说：

> 阅读 `SKILL.md`，按里面的流程帮我整理 Steam 库的收藏集。

之后 agent 会按四步流程推进，每一步汇报并等你确认。

**作为技能安装**：复制到用户级技能目录，目录名须与 `SKILL.md` 里的 `name` 一致（即 `steam-collection`，
例如 `~/.agents/skills/steam-collection`）。

## 使用示例

```
你：阅读 SKILL.md，帮我整理 Steam 库的收藏集
AI：（步骤1）抓到 602 款（含家庭共享 271），已安装 8 款 —— 数量对吗？
你：对
AI：（步骤2）类目提案：A 状态 4 / B 系列 58 / C 类型 22 / D 厂商 53 / F 特性 1 —— 可以吗？
你：C 类型太多，"休闲"和"冒险"看看会不会重叠
AI：（体检 + 收紧后）……
AI：（步骤4）将写入 135 个收藏集，请完全退出 Steam —— 回复"确认写入"
你：确认写入
AI：已写入；回滚用备份 xxx.json 覆盖回去即可
```

库里新增游戏时，直接说"又买了新游戏 / 更新收藏集"，agent 会走增量模式，只处理新增部分。

## 安全与回滚

- 写入前会**自动备份两份**（本机 + 项目目录），退出 Steam 后用任一备份覆盖回目标文件即可还原；
- 写入只替换本工具生成的自建收藏集，**系统"收藏夹 / 已隐藏"原样保留**；
- 写入前，`tasklist` 查 `steam.exe` / `steamwebhelper` / `steamservice` **三项均为 0** 才放行：
  客户端运行中会用内存旧状态覆盖文件，改动会凭空消失；
- 凭据（Cookie / API key）只存本地 `scripts/local_config.json`，**绝不写进任何产出或汇报**。

## 常见问题

- **弹浏览器让我登录安全吗？** 安全。那是本地 Playwright 驱动的浏览器，你在 Steam 官方页面登录，
  脚本只把登录态 Cookie 存到本机，不上传任何第三方。
- **会打乱我原有分类吗？** 不会。写入只动本工具生成的收藏集；增量模式只处理新增 / 移除的游戏。
- **分类不对怎么办？** 单款不对：直接告诉 agent 游戏名和应属分类；整体不满意：回到步骤②调整类目。
- **库很大 / 预算有限？** 步骤③可只复核重点游戏（常玩的、分类存疑的），或调低并发慢慢跑。
- **分类哲学能自定义吗？** 可以。步骤②可完全自定义类目，也能选分类精细度、是否建属性集、复核深度等。

## 数据可信度

三份参考文件里的每个 ID、数字、比例都经过**与实际数据交叉核验**，不使用记忆或估计。
核验过程本身也记录在案——包括一次自我纠错：编写时曾凭记忆写出一张 Steam 标签 ID 表，
事后逐条核验发现 **19 个里错了 10 个**，已全部替换为实测数据。详见
[`CHANGELOG.md`](CHANGELOG.md) 与 `OPTIMIZATION-LOG.md` 第 6.6 节。

本技能在一个 **3991 款游戏 / 225 个收藏集**的真实库上完整跑通并反复迭代。以下问题都是实际踩到并修复的，
细节见 [`CHANGELOG.md`](CHANGELOG.md) 与 [`references/pitfalls.md`](references/pitfalls.md)。

| 铁律 | 为什么 |
|---|---|
| **分类优先级链**<br>`C 厂商 > C-Z95/96/97/99 > D 类型 > E 其他` | 能归厂商的一律不再往下看；且**下级分类的操作不得导致上级分类消失** |
| **写入前 Steam 必须完全退出** | 三项进程均为 0；运行中写入会被内存旧状态覆盖 |
| **厂商归属先核实，不凭名字判断** | 本地元数据只记主发行商、丢弃联合发行；子串匹配会把 `THQ Nordic` 误判成 `THQ` |

| 项 | 数值 |
|---|---|
| 库规模 | 3991 款 / 225 收藏集 / 跨集重复 0 |
| 联合发行校验 | 扫 594 个 appid，找出 31 个联合发行条目 |
| 地区判定 | 扫 1684 款，判定 53 款日韩游戏，**纠正 21 款误判** |
| 厂商名匹配修正 | 加词边界后候选从 152 → 76（**一半是误报**） |

几个典型的坑：`is_deleted` 墓碑原样带上会撞重复 key；改名后新旧名并存会产生重复集，需维护 `RENAMED` 映射；
`Bank of Innovation` 是日本公司；雀魂做日麻规则，但开发方是中国公司。
